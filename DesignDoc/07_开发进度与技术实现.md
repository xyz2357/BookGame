# 开发进度与技术实现

> 本文档记录实际开发中做出的技术决策和当前进度，供后续开发查阅。

## 技术选型（已确定）

| 项 | 决策 | 原因 |
|---|---|---|
| 语言 | TypeScript | 速度快、类型安全 |
| 框架 | React 19 + Vite | UI 开发方便，热更新快 |
| 状态管理 | React Context + useReducer | 够用，不引入额外库 |
| 单元测试 | vitest | 与 Vite 原生集成 |
| E2E 测试 | Playwright (Chromium) | 模拟真实用户操作 |
| 构建 | Vite 8 | 开发快、构建快 |

**不用**：Godot、Ren'Py、Unity（原文档推荐 Godot，实际选了 Web 方案）

## 与设计文档的差异

### 新增：HP 血量系统 + Harsh 机制

设计文档原本明确"不做 HP"，但开发中发现用错书直接卡死体验太差，加入了轻量 HP。后续又发现"每次用错都扣血"惩罚过重，引入 harsh 分级机制：

- 初始 3 HP，顶部常驻显示（纯 CSS 蜡烛图标，lit/spent 两态，flicker 动画）
- **普通事件**：用错书 → 不扣血，显示 "miss" 面板，免费换书重试
- **Harsh 事件**（`harsh: true`）：用错书 → 扣 1 HP，显示失败面板 + "蜡烛熄灭了一根…"
- 血归零 = 进入 game over 结局
- 当前 3 个 harsh 事件：e12（坍塌走廊）、e14（会读人的书）、e15（最深处抉择）

**设计意图**：早期安全探索、后期逐渐紧张。3 HP vs 3 harsh = 每个 harsh 最多容错一次。

### 新增：存档系统

- localStorage 自动存档（key: `bookgame_save`）
- 进入新节点时自动保存
- 主菜单检测存档 → 显示"继续"按钮
- 到达结局或 game over 时自动删除存档

### 新增：PWA 支持

- `vite-plugin-pwa`：Service Worker + Workbox 缓存策略
- 离线可用：所有静态资源 + Google Fonts 均缓存
- 可安装到手机主屏幕
- `registerType: 'autoUpdate'` 自动更新

### 新增：响应式 UI

- 桌面端（≥768px）：900px 容器，NodeView 2 列布局，书卡 2 列网格
- 移动端（<768px）：全宽堆叠，48px 触摸目标，safe-area padding
- GameHeader 组件：HP 蜡烛 + 背包按钮，游戏界面通用顶栏
- 触屏设备禁用 hover，使用 `:active` 反馈

### 新增：GitHub Pages 部署

- `.github/workflows/deploy.yml`：push to main → build → deploy
- Vite `base: '/BookGame/'` 适配子路径

### EventResolver 返回值变化

原设计只返回 Outcome，实际实现返回 `ResolveResult`：
```typescript
interface ResolveResult {
  outcome: Outcome;
  matchType: "super_match" | "tag_match" | "default";
}
```
这样 UI 层可以根据匹配类型给不同反馈（失败可重试、超级匹配可加特效）。

### 结局判定时机

不是每次事件结束都判定，而是**当前节点没有未完成事件且没有可走路径时**才触发结局判定。避免过早触发兜底结局。

## 测试体系

| 层 | 命令 | 文件数 | Tests | 说明 |
|---|---|---|---|---|
| Unit (fixture) | `npm test` | 4 | 40 | 用假数据，内容变不影响 |
| DataLoader | `npm test` | 1 | 6 | 验证 JSON 加载正确 |
| 集成 e2e | `npm test` | 1 | 8 | 用真实数据模拟通关 |
| 数据完整性 | `npm test` | 1 | 12 | 引用校验 + 可达性分析 |
| Playwright | `npm run test:e2e` | 4 | 4 | 浏览器用户操作模拟 |

**内容变化时**：
- Unit tests → 不受影响
- 数据完整性测试 → 自动检测断裂的引用和不可达节点
- 集成/Playwright → 需跟着更新
