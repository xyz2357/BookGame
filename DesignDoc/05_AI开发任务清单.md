# 给 AI 的开发任务清单

> 本文档是写给 AI 编程助手（如 Claude Code、Cursor、Copilot）的任务分解。
> 按顺序进行，每完成一项验证后再做下一项。

## 怎么使用这个文档

每次开新对话时，给 AI 的提示模板：

```
我在做一个文字驱动的章节式叙事冒险游戏，详见附件：
- 00_游戏总览.md（项目背景）
- 01_核心机制设计.md（游戏机制）
- 02_技术架构.md（技术架构）
- 03_数据格式schema.md（JSON 数据格式）

我现在要做的任务是：[具体任务编号和描述]

请按以下要求完成：
1. 先复述你对任务的理解
2. 列出实现步骤
3. 逐步实现，每步给出代码和说明
4. 完成后写一个最小测试，验证功能可用

任何不清楚的地方先问我，不要自己脑补。
```

## 阶段 1：项目初始化（半天）

### 任务 1.1：选定引擎并初始化项目

**前置决策**：你要先选 Godot 4 或 Ren'Py。建议 Godot 4（GDScript）。

**任务描述**：
- 创建一个空 Godot 项目
- 设置项目结构：`data/`、`scripts/`、`scenes/`、`assets/`
- 创建 README.md，说明项目结构

**验收**：项目能用 Godot 打开，目录结构清晰。

---

### 任务 1.2：定义数据加载

**任务描述**：
- 实现一个 `DataLoader` 类，能从 JSON 加载书、事件、节点、结局数据
- 加载到内存中的对应数据结构（GDScript 的字典或自定义类）
- 提供查询接口：`get_book(id)`、`get_event(id)`、`get_node(id)` 等
- 加入数据完整性检查：所有引用的 id 都必须存在

**输入**：`03_数据格式schema.md` 定义的 JSON 格式

**输出**：能加载 JSON 并通过 ID 查询到对应数据结构。

**验收**：写一个最小测试 JSON（1 本书、1 个事件、1 个节点），加载后能正确查询。

---

## 阶段 2：核心系统（1 周）

### 任务 2.1：实现 GameState

**任务描述**：
按 `02_技术架构.md` 中 GameState 的定义实现。要求：
- 全局单例（Godot 的 autoload）
- 提供所有方法：移动节点、增减书、设置 flag、记录选择等
- 提供序列化/反序列化方法（用于存档）

**验收**：写测试，验证：
- 创建初始状态正确
- 各方法调用后状态变化正确
- 序列化后再反序列化得到相同状态

---

### 任务 2.2：实现 EventResolver

**任务描述**：
按 `02_技术架构.md` 中 EventResolver 的定义实现。要求：
- 输入：event_id、chosen_book_id、game_state
- 输出：Outcome（包含 text、effects、next_node）
- 严格遵守优先级：超级匹配 > tag 匹配 > 默认结果

**验收**：写测试用例：
- 用超级匹配的书 → 返回超级匹配的 outcome
- 用普通匹配的 tag → 返回普通 outcome
- 用没匹配的书 → 返回 default_outcome
- 同时满足超级匹配和 tag 匹配 → 优先返回超级匹配

---

### 任务 2.3：实现 Effect 执行器

**任务描述**：
EventResolver 返回 Outcome 之后，需要把 Outcome 里的 effects 应用到 GameState。
实现一个 `EffectApplier`，支持所有 Effect 类型（参考 `03_数据格式schema.md`）：
- gain_book / lose_book / mark_book / transform_book
- set_flag / unlock_node / lock_node
- record_choice / trigger_super_match

**验收**：每种 effect 类型都有测试用例，验证应用后 GameState 正确变化。

---

### 任务 2.4：实现 EndingJudge

**任务描述**：
按 `02_技术架构.md` 中 EndingJudge 的定义实现。要求：
- 数据驱动：从 `endings.json` 读取规则
- 按 priority 从高到低遍历，第一个满足所有 conditions 的结局即为玩家结局
- 必须有兜底结局（无条件）

**验收**：构造几种 GameState，验证结局判定符合预期。

---

### 任务 2.5：命令行版本最小流程

**任务描述**：
**还不做 UI**，先做一个纯文本的命令行版本，能跑通整个游戏循环：
- 进入节点 → 显示节点描述和事件列表
- 选事件 → 显示事件描述
- 选书 → 调用 EventResolver → 显示结果
- 应用 effects → 跳转节点（或留在原地）
- 直到结束 → 显示结局

用占位测试数据（3-4 个节点、5 个事件、5 本书、2 个结局）测试。

**验收**：能在命令行里完整通关一次"迷你 demo"。这是项目的第一个里程碑——**核心循环跑通了**。

---

## 阶段 3：UI 实现（1-2 周）

### 任务 3.1：主菜单

**任务描述**：
- 标题画面、开始游戏、继续（读档）、退出
- 简洁的视觉风格，符合"古旧图书馆"基调
- 可以先用占位字体和颜色，美术后期统一调

---

### 任务 3.2：节点视图

**任务描述**：
- 显示当前节点的名称和描述
- 显示节点上未完成的事件按钮（点击进入事件视图）
- 显示可前往的相邻节点按钮（点击移动）
- 底部按钮：打开背包

**关键交互**：
- 已完成的事件灰显或隐藏（根据剧情设计）
- 不满足解锁条件的连接灰显（提示玩家有"需要某 tag 的书"）

---

### 任务 3.3：事件视图

**任务描述**：
- 显示事件描述文本（支持渐入动画）
- 提示文字（"选一本书来应对"）
- 显示玩家背包书的列表（横滑/网格）
- 选中一本时高亮，显示"使用《XXX》"按钮
- 确认后调用 EventResolver，切到结果显示
- 结果显示文本，点继续返回节点视图（或跳转）

**视觉重点**：
- "翻书"的仪式感——选书时书有视觉反馈（轻微浮起、台词出现等）
- 超级匹配触发时的特殊效果（书发光、文字渐变色等，让玩家"感觉到"特别）

---

### 任务 3.4：背包视图

**任务描述**：
- 网格或列表显示所有书
- 选中后右侧/下方显示详情（标题、作者、台词、tags、简介）
- 仅查看，不能从这里使用书
- 可以从节点视图打开，也可以从事件视图打开（但事件视图主要用自带的选书 UI）

---

### 任务 3.5：结局视图

**任务描述**：
- 显示结局名称和文本（缓慢渐入）
- 简短统计（可选）：用了多少本书、触发了几个超级匹配、走了哪条路径
- 返回主菜单按钮

---

## 阶段 4：内容填充（与剧本写作并行）

### 任务 4.1：填充第一章数据

**任务描述**：
按 `04_第一章关卡内容设计.md` 的设计，编辑 `books.json`、`events.json`、`nodes.json`、`endings.json`。

**这是写剧本的工作，不是写代码**——AI 可以辅助生成初稿，但需要人工反复打磨。

---

### 任务 4.2：数据完整性检查脚本

**任务描述**：
写一个工具脚本，启动游戏前检查：
- 所有 event 引用的 book_id 都存在
- 所有 connection 的 target 节点都存在
- 所有 next_node 引用的节点都存在
- 所有结局的 condition 引用的 flag/choice/match 都至少在某处被设置过
- （可选）每个事件至少有 2 种解法（覆盖性检查）

---

## 阶段 5：打磨

### 任务 5.1：存档系统
- 自动存档（进入节点时）
- 主菜单的"继续"读取存档
- 一个存档槽即可

### 任务 5.2：音效
- 翻页音
- 选书音
- 移动节点音
- 结局背景乐
- 用免费 asset（freesound.org / itch.io 免费包）

### 任务 5.3：美术
- 卡片/书的视觉模板（统一风格）
- 节点场景图（可用 AI 生图）
- UI 框架/边框

### 任务 5.4：超级匹配的"高光"反馈
- 视觉：书发光、文字闪现
- 音效：特殊音
- 节奏：稍微慢一点，让玩家感受到这一刻

### 任务 5.5：测试
- 自己通关至少 3 次（每次走不同路线）
- 找朋友测试（至少 3 人）
- 记录卡点、bug、不直觉的地方
- 修复

## 重要原则（写给 AI，也写给你自己）

1. **数据驱动一切**：所有内容（文本、规则、流程）都在 JSON 里，代码只处理逻辑
2. **逐步验证**：每完成一个系统都要写测试，不要做完整体再调试
3. **占位先行**：UI 和美术都先用占位，跑通流程比好看重要
4. **不要扩展范围**：MVP 清单之外的想法记到 `99_V2想法仓库.md`，不要现在做
5. **写完一个系统就提交**（git）：方便回滚

## 第一个真正的里程碑

**完成阶段 2.5（命令行最小流程）= 项目"活了"。**

这之前所有时间都是在搭骨架。一旦命令行能跑通一遍"假数据迷你 demo"，你就证明了：
- 数据格式可行
- 核心系统正确
- 整个游戏的逻辑闭环成立

后面所有事情都是在这个基础上加血加肉。

**优先达成这个里程碑。** 在此之前不要分心做 UI、美术、剧本细节。
